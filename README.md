# Lukas Ude – Portfolio & Business Website

**Rooted in ideas. Built for growth.** · Marketing · AI · Systems

A cinematic, editorial personal brand website: funnels you can click through,
ad creatives with their copy, design work, AI workflow blueprints, an About page
with CV timeline and a secure contact form.

- **Frontend:** plain HTML, CSS and JavaScript, generated by a small build script. No framework.
- **Backend:** Node.js with **zero runtime dependencies**. It provides the contact API and security headers, and can also serve the website.
- **Content:** one folder per project in `/content`.

> **Quick start for beginners:** read [`docs/EDITING-GUIDE.md`](docs/EDITING-GUIDE.md) (German, step by step)
> and [`docs/PROJECT-MAP.md`](docs/PROJECT-MAP.md) (which file controls what).

## 1. Project structure

```
/frontend            Everything that is PUBLIC (sent to the browser)
  /config/site.js    ← central public settings (name, domain, navigation, links)
  /pages             one HTML file per page (home, work, funnels, ...)
  /components        reusable parts (head, navigation, footer, contact form, ...)
  /templates         layouts for project pages (funnel, creative, design)
  /demos             live funnel demos (standalone landing pages)
  /styles            CSS: base/ components/ sections/ pages/ + main.css
  /scripts           browser JavaScript (main.js + modules/)
  /assets            fonts, logo, images, textures
  /public            files copied as-is (favicon)
  /build             the build script (Node, runs on your computer / the host)
  /dist              ← GENERATED website (do not edit, not in git)

/backend             Everything PRIVATE (runs only on the server)
  /src/server.js     entry point
  /src/config.js     reads environment variables
  /src/routes        API endpoints (contact, health)
  /src/services      contact delivery (log / Resend / webhook)
  /src/lib           security headers, rate limit, tokens, static files
  /test              automated tests (npm test)
  .env.example       all settings explained – NO real values

/shared              code used by BOTH sides (only public validation rules)
/content             portfolio content (funnels, creatives, design, ai, career)
/docs                documentation
/source-assets       original brand files (CI sheet, portrait, logo board) – not deployed
/scripts             dev.js (local development), check-site.js (quality check)
```

## 2. Frontend architecture

The website is **pre-built into static HTML** (fast, SEO-friendly, nothing to hack on the server):

1. `frontend/build/build.js` reads `config/site.js` and everything in `/content`.
2. Every file in `frontend/pages` is wrapped in `components/layout.html`
   (head, navigation, footer) and written to `dist/<page>/index.html`.
3. Every project folder in `/content` gets its own page from a template in `frontend/templates`.
4. The CSS files are combined into one file (`dist/styles/main.css`).
5. Images marked with `data-responsive` are converted to AVIF/WebP/JPEG in several sizes.
6. `sitemap.xml`, `robots.txt`, `_headers` (security headers), the QR code and app icons are generated.

Template syntax (intentionally tiny): `{{ site.name }}`, `<!-- @include footer -->`,
`<!-- @render featured-work -->`. See `frontend/build/lib/template.js`.

JavaScript in the browser is small, native ES modules (`frontend/scripts/modules/*`),
each one documented at the top. Without JavaScript, all content stays visible.

## 3. Backend architecture

`backend/src/server.js` (Node.js built-ins only):

| Route | Purpose |
|---|---|
| `GET /api/health` | health check for hosting providers |
| `GET /api/contact/token` | short-lived, signed anti-spam token |
| `POST /api/contact` | validates and delivers a contact message |
| everything else | the built website from `frontend/dist` (if `SERVE_FRONTEND=true`) |

Contact delivery is configurable: `log` (development), `resend` (e-mail) or
`webhook` (Make / n8n / Zapier / CRM). Details: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md),
[`docs/SECURITY.md`](docs/SECURITY.md).

## 4. Run locally

Requirements: **Node.js 22.9 or newer**.

```bash
npm run setup      # once: installs the build tools (sharp, qrcode)
npm run dev        # builds, watches for changes, starts http://localhost:3000
```

Contact form messages are printed in the terminal (`CONTACT_DELIVERY=log`), nothing is sent.

Other commands:

```bash
npm run build      # build the website once into frontend/dist
npm start          # start only the backend (serves frontend/dist)
npm test           # backend tests (validation, spam protection, rate limit, headers)
npm run check      # check the built site: broken links, secrets, alt texts, SEO tags
```

## 5. Build

```bash
npm run build
```

The build prints **warnings** at the end, for example example content that is
still published, `[ADD ...]` placeholders, images without alt text, or the domain
still set to `localhost`. Fix them before going live.

`npm run build -- --drafts` (inside `/frontend`) also builds projects with `"status": "draft"`.

## 6. Deploy

Frontend and backend can be deployed **together** or **separately**.

**Option A – one Node server (simplest):** e.g. Render, Railway, Fly.io, a VPS.
- Build command: `npm run setup && npm run build`
- Start command: `npm start`
- Environment variables: see `backend/.env.example` (at least `NODE_ENV=production`,
  `FORM_TOKEN_SECRET`, `ALLOWED_ORIGINS`, `CONTACT_DELIVERY` + its keys, `TRUST_PROXY=true`).

**Option B – static hosting + separate API:**
- Website on Netlify / Cloudflare Pages: base directory `frontend`, build
  `npm install && npm run build`, publish `dist`. The generated `_headers` file sets the security headers.
- Backend anywhere with `SERVE_FRONTEND=false`, e.g. on `api.your-domain.de`.
- Set `apiOrigin: "https://api.your-domain.de"` in `frontend/config/site.js` and
  `ALLOWED_ORIGINS=https://www.your-domain.de` in the backend.

Before going live: set `url` in `frontend/config/site.js` to the real domain
(canonical URLs, sitemap, QR code), fill in Impressum/Datenschutz, run `npm run check`.

## 7. Environment variables

- Real values live in `backend/.env` (locally) or in the hosting dashboard.
- `backend/.env` is **never committed** (`.gitignore`).
- `backend/.env.example` lists and explains every variable without values.
- In production the server **refuses to start** if a required secret is missing.
- The frontend has **no** environment secrets. `frontend/config/site.js` is public by design.

## 15. Connect a real contact form

1. Choose a delivery method in the backend environment:
   - **E-mail via Resend:** `CONTACT_DELIVERY=resend`, `RESEND_API_KEY`, `CONTACT_TO_EMAIL`,
     `CONTACT_FROM_EMAIL` (a verified sender domain).
   - **Automation / CRM:** `CONTACT_DELIVERY=webhook`, `CONTACT_WEBHOOK_URL`
     (optionally `CONTACT_WEBHOOK_SECRET` for a signature header).
2. Set `FORM_TOKEN_SECRET` (32+ random characters) and `ALLOWED_ORIGINS`.
3. Mention the provider in `/frontend/pages/datenschutz.html`.
4. Another provider? Add one function in `backend/src/services/email.js`.
